# Provenance

This repository is a continuation of someone else's work. This document exists so
nobody has to guess which parts are which.

## The short version

[`FrankHUN88453/CoD3Recomp`](https://github.com/FrankHUN88453/CoD3Recomp) built a
working, rendering Call of Duty 3 PC port by static recompilation. It reached the
point where the game boots, streams its assets, renders through Direct3D 11 with
its own shaders translated from Xenos microcode, and plays audio.

This project takes that as its foundation and carries it further. The runtime is
his. The direction is ours.

That last item is load-bearing. The patched tools and the config that assumes
them go together; a build with unpatched tools and this config does not work.

## What was here before, and where it went

This repository previously contained an independent from-scratch XenonRecomp
runtime, written without knowledge that a working port existed. It reached: a
correct CRT heap (allocator, method table, lock, block headers), an MMIO
interception that captured the Xenos command processor, NT file I/O, and a
display subsystem.

It is superseded in its entirety. Preserved at tag
`archive/from-scratch-runtime` for reference and for the findings.

Two things from it are worth recording, because they cost real time to learn and
would cost it again:

1. The CRT heap block header's size halfword lives in the **low** half of the
   big-endian word at offset 0. A guard that reads the same field as the code it
   guards has to agree with it about which half is which, and agreeing is not
   automatic.
2. Guest MMIO reaches the GPU register file at `0x7FC80000`, and there are only
   **eleven** such stores in the whole recompiled guest, all 32-bit. The entire
   Xenos command stream passes through those eleven sites.

## Reproducibility caveat

The recompiled game code — `CoD3RecompLib/ppc/` and `CoD3RecompLib/levels/*/` —
is **not committed**, roughly 94 MB of machine-written C++ covering ~19.5k
functions plus fifteen level DLLs. It is derived from the copyrighted binary and
is regenerated by `scripts/recompile.ps1`.

So a fresh clone does not build in one step. Anyone needs their own `default.xex`
and several hours of recompilation. That is deliberate, and this repository has
kept it that way.
