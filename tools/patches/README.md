XenonRecomp is pulled in as a submodule, pinned at upstream commit
ddd128bcca99fe8bfbb99bea583c972351fa6ace. The patch beside this file is
everything this project changes in it, and it must be applied after the
submodule is checked out, before the tools are built:

    git submodule update --init tools/XenonRecomp
    git -C tools/XenonRecomp apply ../patches/XenonRecomp.patch
    .\scripts\recompile.ps1 -BuildTools

What it carries, oldest first:

- the integer divide guard (a PowerPC divide by zero does not trap, the host
  does), the switch index compared as a word, and the vector instructions
  Call of Duty 3 uses that upstream leaves as traps (vaddsbs, vsubshs, the
  halfword shifts and compares, vrlh, the pack and unpack forms and more);
- vupkd3d128's float16 and short4 unpacks, vpkd3d128's float16_2 pack, and
  blrl as an indirect call;
- XenonAnalyse reading an absolute jump table that has no bounds check
  before it by the table's own length.

The recompiled C++ under CoD3RecompLib/ppc and CoD3RecompLib/levels is
generated by these tools and is not committed; the config under
CoD3RecompLib/config is, and it assumes the patched tools.
